# Anthropic API を止めた今、AI が自律的にできること（2026-11-27）

## 自動で動き続けるもの（人も AI の判断も不要・0円）
GitHub Actions（公開リポジトリの標準ランナー＝無料）で、決まった手順だけを毎日実行する：
- 費用の見張り（guard.py）：無料枠の80%・確認不能・有料プラン・非公開リポジトリ・有料 API のキーで開発と試験を止め、Issue で通知
- 料金の整合性（check_pricing.py）：Apify 上の料金設定とコードの課金を突き合わせ、二重課金の恐れがあれば Issue で通知
- 記録（tracker/track.py）：外部の利用者・実行（自分の試験を除く）、失敗率、競合の数字
- 市場調査（毎週月曜）：Apify Store 全件の取得と分野ごとの集計
- デプロイ：deploy-request.txt の push で、見張りを通ってから非公開で作成・ビルド・試験

## AI（Claude）の判断が必要なもの → Claude のセッションが動いている間だけ
- 数字を読んで改善を決める、不具合の修正、README の改善、新しい分析、価格の見直し案
- 手段：Claude のスケジュール実行（毎朝の定期タスク）と、オーナーとの会話。Claude の利用プランの範囲で動き、外部 API の料金は発生しない（プランの利用量には数えられる）
- GitHub Actions の中では AI は動かない（有料 API を止めたため）。判断を伴う改善は「毎朝の定期タスク」で行う

## AI ができないこと（オーナーの操作が必要）
- 公開、料金の設定・変更、支払い情報、本人確認（KYC）：Console の操作・本人の書類が必要。承認制
- 売上・有料利用者・Apify 側の計算費の取得：公式 API が無い。Console の Analytics の書き出しをオーナーが渡す
- Store のページの閲覧数：取得手段が無い（未確認のまま）

## 改善の循環（公開後）
1. 毎朝：GitHub Actions が数字と料金の確認を記録 → 2. 毎朝の定期タスク（Claude）が DASHBOARD を読み、外部の失敗・利用の変化を確認
3. 不具合なら修正して手元と GitHub で試験 → 4. 公開済み商品の更新（新しいビルド）は、オーナーが「自動更新してよい」と決めるまで承認依頼にする
