# KeyRelay 本番前の確認（2026-11-24）

本番データ（他人のライセンスキー）を扱う前に確かめた項目。✅＝確認済み、⚠️＝残る危険（対策案つき）。

| 項目 | 状態 | 内容 |
|---|---|---|
| 認証 | ✅ | 管理 API は `Authorization: Bearer` の管理トークンが必要。トークンは 128 ビット超の乱数で、D1 には SHA-256 のハッシュだけを保存し、比較は時間一定。トークンなしの管理 API は 401（手元で確認） |
| テナント分離 | ✅ | キーの検索・作成・無効化・統計・書き出し・削除は、すべて `tenant_id` で絞っている。端末（instance）は、テナントで絞ったキーの ID と組で照合する。他のテナントのキーを URL の名前を変えて確認しようとしても、`license_key not found.` になる |
| 端末 ID の衝突 | ⚠️ 低 | 端末 ID は全体で一意（LS の UUID をそのまま使うため）。他人の端末 ID を事前に知って登録しない限り衝突しない。衝突時は取り込みが飛ばされ、件数に出る |
| API キーの扱い | ✅ | LS の API キーは取り込みの1回だけ使い、保存しない。販売者の Stripe の Webhook 署名シークレットは、署名の確認に必要なので D1 に保存する（平文）。⚠️ 将来は暗号化を検討 |
| Webhook | ✅ | Stripe の署名（HMAC-SHA256）と5分以内の時刻を確認。同じ Checkout Session の再送ではキーを二重発行しない（手元で確認） |
| データ移行 | ✅ | LS の公式 API（`/v1/license-keys`、`/v1/license-key-instances`、page[size]=100、links.next）の項目名を公式ドキュメントで照合済み。端末の `identifier` は有効化時の `instance_id` と同じ値（公式に明記）。偽の LS API で取り込み・二重取り込み防止・無効キー・認証エラーをテスト（PASS）。⚠️ 本物の LS アカウントでの取り込みは未実施（LS の新規登録が終了しているため、利用者の協力が必要） |
| 書き出し | ✅ | `GET /<ws>/admin/export` で、自分のキーと端末をいつでも JSON で持ち出せる |
| 障害復旧・バックアップ | ✅/⚠️ | D1 の Time Travel（常に有効・追加費用なし）で、**無料プランは過去7日以内の任意の分**に戻せる（有料は30日）。出典：developers.cloudflare.com/d1/platform/limits/ 。⚠️ 7日より古い状態は戻せない。週1回 export を R2 等に保存する仕組みは、利用者が出てから作る |
| 容量 | ⚠️ | 無料プランは D1 1つ 500MB、Workers 1日10万リクエスト。超えると **全利用者の確認 API がエラー**になる。利用者のアプリには「確認できないときは一定期間は通す（キャッシュ）」実装を案内する。利用が増えたら Workers 有料（月 $5）に切り替える（費用は承認事項） |
| 乱用 | ⚠️ | 登録は同じネットワークから1日5件まで。License API の回数制限はまだない（LS は毎分60回）。悪意ある大量アクセスで無料枠を使い切られる危険。対策案：独自ドメインにして Cloudflare のレート制限ルールを使う（ドメイン費用が発生するため承認事項） |
| 入力の大きさ | ✅ | 端末名は200文字、meta は4,000文字まで |
| 自己テスト | ✅ | `/selftest` は一時ワークスペースで一連の動作を試し、終わったら消す。1分に1回まで。集計には入らない |
