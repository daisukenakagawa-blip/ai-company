# Ver.2.3 収益資産の設計と検証（2026-11-25）
区別：【事実】出典・実測あり／【推測】AI の判断。規模の計算は試算であり予測ではない

## 1. お金の流れの分解（今回の検証から得た規則）
- 「終了・移行」で支払いが起きるのは、**影響を受ける側の売上が止まる場合だけ**。【事実】LS（決済・ライセンス）では互換の Clavem が有料で成立。【事実】Libraries.io API（11/30終了、https://github.com/badges/shields/issues/12320）と gh-card.dev（停止済み、https://gh-card.dev/ 、README 約1,100件で壊れる）は、無料の代替があり支払いの証拠なし
- → Continuity Relay の候補選びの規則：「止まると利用者の売上・請求・納品が止まる API」だけを選ぶ（決済、ライセンス、請求書、配送、予約、認証）
- 入札：【事実】払う人（民間企業）→ 情報サービス（NJSS 7,295契約）。払う理由は「探す手間」と「締切・資格の読み取り」。【事実】公式 API には締切が入っていない（173件中1件のみ）

## 2. 実測した結果
### 入札朝刊：締切の自動抽出（官公需 API の本文、11/18以降の「業務委託」173件）
- 単純な規則で締切らしき日付が取れたのは 76件（44%）
- 抜き取り8件のうち1件は「受付期間」の**開始日**を締切として取っていた → 誤った締切を利用者に渡す危険が実在する
- 取れなかった97件の多くは国の調達ポータル由来で「公開終了日」が代わりに使える形式
- 添付 PDF の取得は、自治体ごとのドメインが実行環境で遮断されて不可（本番の Cloudflare Workers なら取得可能と推測）
- 利用規約：サイトの夜間メンテナンス（2〜5時）で未確認。**確認するまで外部に出さない**
- 結論：締切は「抽出した値＋原文の該当箇所＋元資料へのリンク」をセットで出し、確信度が低いものは「要確認」と明示する設計が必須

## 3. 事業ごとの設計（12項目）
| 項目 | 入札データの構造化（朝刊＋卸） | Continuity Relay（売上が止まる API に限定） | Fresh Facts（証拠つき検証 API） |
|---|---|---|---|
| 所有する資産 | 公告ごとの締切・資格・地域の構造化データと、利用者の検討・見送りの履歴 | 終了した API の互換層の束（KeyRelay が1号） | 変わる事実の時系列と証拠（取得日時・出典 URL・本文の該当箇所） |
| 資産が自動で増える仕組み | 毎日の公告を自動で取り込み、履歴が日ごとに増える | Gap Engine が次の終了を見つけ、互換層が増える | 毎日の再確認で履歴が伸びる |
| 払う主体 | 中小の受注企業（朝刊）、入札支援の士業・コンサル（卸） | 終了した API を使うアプリの開発者 | AI エージェントを作る開発者 |
| 支払いの条件 | 月額（朝刊）、顧客数に応じた月額（卸） | 有効なライセンス数・確認回数に応じて | 確認1回ごと |
| 1取引の収益 | 1,980円/月、卸 9,800円/月（仮） | 3,600円/月相当（Clavem の価格水準） | 未確認 |
| 1取引の費用 | 決済手数料3.6％＋抽出の AI 費（仮に30円/月） | 決済手数料＋無料枠内のサーバー | 取得と保管（無料枠内） |
| 自動集客の経路 | 業務の中で使う Slack・スプレッドシートに毎朝届き、社内で転送される／卸先の士業が自分の顧客に配る（士業1件が顧客N社に広げる） | 期限が来ると開発者が必ず移行先を探す。「URL1か所の変更」で済む受け皿は移行作業の中で見つかる | エージェントのツール登録簿（MCP）。**集客は未検証** |
| 継続される理由 | 公告は毎日出る。検討・見送りの履歴が溜まるほど絞り込みが合う | 配布済みのアプリが毎日自動で呼ぶ | 事実は毎日変わる |
| 模倣されにくい理由 | 履歴（会社ごとの判断）と抽出の精度の蓄積。データ自体は公開なので弱い | 先に置いた互換層からの移り先の変更は手間 | 過去の証拠は後から作れない（時間の先行） |
| 人の介入 | 抽出の確信度が低い案件の確認（初期） | 終了案件ごとの互換の検証 | なし（目標） |
| 0円の検証方法 | 2週間の件数・抽出精度の実測（実施中）→ 規約確認 → 承認後に士業向けの見本と予約受付 | 「売上が止まる API」の終了を Gap Engine から3件選び、一次資料で確認 | 先行（PricingSaaS）の日本 SaaS の収録状況を確認 |
| 需要の証拠 | 【事実】NJSS 7,295契約・四半期9.75億円 | 【事実】Clavem の有料販売（LS の件のみ） | 弱い（先行者あり） |
| 分類 | B | B（LS 以外は未確認） | C |

## 4. 規模の逆算（決済手数料3.6％と仮の変動費を引いた、月間純利益に必要な有料顧客数）
| 事業（価格） | 1万円 | 10万円 | 100万円 | 1,000万円 |
|---|---|---|---|---|
| 入札朝刊（1,980円/月） | 6 | 54 | 533 | 5,323 |
| 入札データの卸（9,800円/月） | 2 | 11 | 107 | 1,066 |
| Continuity Relay（3,600円/月相当） | 3 | 29 | 290 | 2,899 |
- 【推測】朝刊だけで月100万円には533件が要る。NJSS 全体が約7,300件なので、小さな後発としては非現実的に近い。**卸（士業・コンサル経由）なら107件**で、各士業が複数の顧客に配るため到達の効率が良い。100万円を狙うなら卸が主、朝刊は入口
- 【推測】Continuity Relay は1件の終了で290件の有料利用者を集めるのは難しい。複数の「売上が止まる API」の互換を束ねて初めて成り立つ

## 5. 承認で実行できる実験（準備ができしだい提出）
- 入札データ：利用規約で商用利用・再配布が許されると確認できたら、①士業・コンサル向けの見本ページ（1業種・1週間分、締切は原文つき）と予約受付を店に置く、②期間3週間、③成功条件：予約3件以上（うち1件は価格に同意）、④撤退条件：訪問はあるのに予約0なら価値の問題、訪問0なら経路が未検証と記録
