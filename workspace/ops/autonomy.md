# 自律運営の権限設計（Ver.2.0 第7条、2026-11-24）

現在は**個別承認方式を維持**する。下の B は設計のみで、**オーナーが項目ごとに明示的に承認するまで無効**。AI が自分で範囲を広げることは禁止。

## 判定の流れ
1. 行動が下の表のどれに当たるかを見る。どれにも当たらない・迷う → **C**
2. B の行は、`state/permissions.json`（未作成。オーナー承認で作る）に「承認日・条件・上限・期限」が書かれているときだけ実行してよい。条件を1つでも外れたら C
3. 実行したら `workspace/ops/runs.md` に記録。B の実行は日報にも載せる

## A：自動実行可
| 行動 | 条件 |
|---|---|
| 公開情報の調査（公式サイト、公式 API、RSS） | 利用規約・robots に従う。ログインが必要な取得はしない |
| コード作成、ローカルテスト、統計分析 | 手元のみ |
| 社内文書（workspace/、reports/）の作成 | 実績・数字を作らない |
| リポジトリへの commit・push（社内文書・試験） | 本番の挙動が変わるものは B または C |
| 既存の Stripe・Cloudflare・KeyRelay の数値の読み取り | 読み取りのみ |

## B：事前承認した条件内で実行可（すべて未承認＝無効）
| 行動 | 承認時に決める条件 |
|---|---|
| 既存サービスの軽微な更新（文言、表示、不具合修正）の本番反映 | 対象サービス、試験の合格、課金・権限・データに触れないこと |
| 承認済み集客経路の運用（例：X の予約投稿、note の自動投稿） | 経路、頻度の上限、内容の種類、禁止事項 |
| 承認済み内容の定期公開（店内ガイド等） | 1日の上限、品質の確認方法 |
| 無料枠内の設定変更 | 費用が発生しないこと、元に戻せること |

※ 現在 CLAUDE.md で自動になっている「X 投稿・note 投稿・ガイド公開」は、オーナーの過去の指示（11/21・11/22）によるもの。B として改めて条件を書いて承認を受けるまで、従来の指示の範囲を超えない。

## C：毎回承認が必要
有料契約、資金移動、新規外部アカウント登録、新しい外部への公開・投稿（Show HN、新リポジトリ、マーケットプレイス登録など）、重大な本番変更（課金・権限・データ構造・鍵の仕組み）、法的責任が生じる行為、利用規約の同意、個人情報の新たな取得。

## 例
- 店の鍵（Fail Closed）の本番反映：課金・権限に関わる＝C。2026-11-24 オーナーの Ver.2.0 第2条の指示により実施
