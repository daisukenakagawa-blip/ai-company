# 店：購入者が製品版を開けないときの復旧手順（2026-11-25）

## お客さまから「買ったのに開けない」と連絡が来たら
1. オーナー：Stripe ダッシュボード → 支払い で、お客さまのメールアドレスか金額・日時で決済を探す
2. 決済の詳細にある Checkout Session の ID（`cs_live_` で始まる）をコピーする
3. お客さまに次の形のリンクを送る：`https://genhayl-shop.pages.dev/api/unlock?p=<商品のフォルダ名>&session_id=<cs_live_...>`
   - 決済から72時間以内なら、そのまま開ける
   - 72時間を過ぎている場合は開けない（使い回し防止）。その場合は返金で対応する（表記ページの「7日以内なら返金」）
4. 「購入の確認に失敗しました」と出る場合は Stripe か Cloudflare の不具合。Claude に連絡（日報で確認）

## 想定される原因
- 別のブラウザ・端末で開いた（印は端末ごと）→ 72時間以内なら上のリンクで開ける
- Cookie を消した → 同上
- STRIPE_KEY の期限切れ・権限変更 → 全員が開けなくなる。キーの権限（Checkout Sessions・PaymentIntents・Charges の読み取り）を確認

## 対策の費用対効果（Ver.2.1 第8条）
| 問題 | 対策 | 費用 | 効果 | 判断 |
|---|---|---|---|---|
| 決済ID の使い回し（72時間以内） | Cloudflare KV（無料枠）で決済ごとの開封回数を数え、3台までにする | 0円。オーナーが KV を作って紐づける作業が約5分、実装1時間 | 売上0円のいま、守る売上がない | **見送り**。最初の売上が出たら再検討 |
| 製品コードの露出（お試しと製品版が同じ JS） | 製品版だけの処理をサーバー側に移す | 55商品の作り直し。データを外に送らない約束が崩れる | 500〜980円の道具を不正に使う人の損失は小さい | **見送り**（既存55商品の追加開発は禁止） |
| 72時間後の別端末での復旧 | 上の手順（オーナーが手作業） | 1件数分 | 購入者の救済 | 手順で対応 |

- 返金後に製品版が閉じるか
