# 経路 #5「開発者向けパッケージ市場（npm 等）」の評価（2026-11-25）

## 問い
営業も SNS も宣伝もしないのに、npm にパッケージを置くだけで新しい利用者が増えるか？

## 一次データ（npm 公式 API、2026-11-25 取得）
- 【事実】同じ型の「互換の受け皿（drop-in）」を個人が公開した例の週 DL：
  - @keep-lts/xlsx 17,890／本家 15,083,734（0.12%）
  - @keep-lts/extract-zip 753／本家 27,413,068（0.003%）
  - @keep-lts の他10件：5〜447
  - exceljs-hardened 108,241、vue-template-compiler-patched 11,726
- 【事実】例外：uri-js-replace 週17,204,738（本家 uri-js の置き換え）
- 【推測】DL 数には CI の自動取得が多く含まれ、利用者数ではない（CLAUDE.md の規則どおり購入者数として扱わない）

## 評価
| 項目 | 判定 |
|---|---|
| 規約 | npm 公開は可。名前の紛らわしさ（typosquatting と見られる命名）に注意 |
| 費用・審査 | 0円・審査なし |
| 探している人の証拠 | 脆弱性スキャナーが「修正版なし」と出したときに代わりを探す人はいる（keep-lts の DL がその証拠）。ただし規模は本家の0.1%前後 |
| 流入の測り方 | api.npmjs.org の DL 数（利用者数ではない） |
| 自動で回るか | 回るが、伸びは「有名パッケージに依存先として採用されるか」で決まる（uri-js-replace の例）。採用は人の判断 |
| 店で使えるか | 使えない（店の客は開発者ではない） |
| KeyRelay で使えるか | LS 互換クライアントを置いても、移行を探す人は npm ではなく「Lemon Squeezy alternative license」で検索する。【推測】効果は小さい |
| 承認区分 | C（外部公開） |

## 結論
- npm は「置けば客が来る」経路ではない。**置いた後、依存元に採用される経路（本家の issue・依存元の PR）が無ければ流入は本家の0.1%前後で止まる**
- 当社の判断：経路 #5 は「単独では不可」。使うなら、依存元に採用される理由（互換試験の結果を公開、重大な脆弱性）がある場合だけ
- channels.md の #5 を「評価済み：単独では不可」に更新
